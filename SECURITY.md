# Security

This is a demonstration application with a synthetic catalog and an in-memory cart. It does not process payments.

Setup creates three distinct random keys in `.local/gateway.env` with owner-only permissions. Retailer keys grant access to one tenant. The operator key controls readiness and draining through loopback or an SSH tunnel. Do not put keys in URLs, screenshots, command arguments, issues, or git.

Keep `.local`, model weights, recordings, generated previews, and personal photos outside version control. A `.gitignore` does not remove files already committed. Release archives are built from an explicit source allowlist, without git history. Scan that archive and the new repository before publishing.

The model workers accept only loopback traffic and do not authenticate local clients. Use a dedicated host with trusted local accounts. The pinned model snapshot contains custom model code; review its license and source before enabling it. Downloading packages and models requires network access. Inference uses local workers.

Before exposing HTTPS, configure both cloud and host firewalls, restrict the audience, and verify private ports from another machine. Caddy request limits complement the gateway's bounded inputs, tenant checks, session limits, and serialized inference. This is not a production identity or abuse prevention system.

Run `python scripts/public_check.py`, Gitleaks, and `python scripts/security.py dependencies` before publishing. The dependency command checks every package in the gateway, speech, image, and model-server locks, including transitive dependencies and the pinned installer. Missing tools, skipped packages, empty reports, and advisory findings fail the check. Reports stay under `.local/security/`.

On a Linux x86_64 GPU host, `python3.12 scripts/security_tools.py` installs the private audit environment and checksum-verified Trivy binary. `scripts/images.py` builds containers in a source-only temporary context, scans all vulnerability severities including unfixed findings, and records immutable image IDs only after a passing scan. It does not use an advisory ignore list. Review the pinned NeMo and model source separately; package scans do not inspect that source or prove the safety of native libraries.

The Ubuntu test host has all available updates and a verified HWE kernel. Unfixed advisories remain, including a critical IPv4 kernel issue. [The host review](docs/host-security.md) records the fixes, mitigations, scan scope, and remaining findings. Installed-package matches are not proof of exploitability. `python scripts/security.py host` retains all findings. For a restricted demonstration, an operator can explicitly pass `--accept-host-advisories` to accept unfixed host findings. Available fixes and incomplete scans still block installation. This exception does not apply to application dependencies or container scans. Do not describe this deployment as vulnerability-free.

`deploy/release-status.json` records readiness for the documented restricted demo. Normal `site.py apply` and `release.py --publish` refuse candidates with incomplete verification. [The fresh-site receipt](docs/fresh-site-verification.md) records the current results and accepted host limitations. Maintainers can use `site.py apply --verify-candidate` to test new infrastructure before publication clearance. This leaves runtime scans active. The separate host-advisory option records an explicit restricted-demo exception. Review archives can still be created without `--publish`; that is not release approval. A passing scan reports known findings at scan time and never establishes the absence of undiscovered vulnerabilities.

The provisioner stores credentials and resource ownership state only under ignored `.local/`, restricts ingress to the supplied administrator addresses, pins SSH host identities, and refuses foreign resources or uncertain duplicate creation. The low-level provisioner implements no resource update or deletion API. `make destroy` separately verifies the selected site's saved IDs, ownership tags, labels, and firewall attachments before deleting only that GPU and its dedicated firewall. It refuses unexpected attached resources and requires the full instance label as confirmation. Preserve private state securely and revoke the provisioning token after use.

Report security issues privately through the repository's GitHub Security Advisories page when enabled. Do not disclose credentials or exploitable details in a public issue. If private reporting is not enabled, contact the repository owner through an existing private channel.
